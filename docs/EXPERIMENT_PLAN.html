2. 为什么先做 Phase 1(再次澄清)

之前的口误已修正:Phase 1 不是为了 "对齐 SOTA 0.667"。0.667 是 nuScenes Tracking test set + V2-99 backbone + offline setting,我们 R50+val+online 这套设定下的天花板大概就是 0.55-0.60(见 StreamPETR-R50 在 val 上的数字)。

Phase 1 的 4 个真正目的

  1. 吸收 "camera-only 已发表 trick 全集",避免 Phase 2 多模态提点被审稿人质疑 "不就是因为你 baseline 没用 ContrasTR / PF-Track 吗?"
  2. 建立 ablation table 完整对照点,论文里能写出 "已知 camera-only trick 全开 0.58 → 加 LiDAR 0.68 (+0.10 干净归因)"
  3. 工程基础设施压测:7 次完整训练-评测-debug 循环把 codebase 隐藏 bug 全暴露,Phase 2 调试效率高一个数量级
  4. R50→V2-99 升级路径解耦:Phase 1 在 R50 验证过的 trick,换 V2-99 后基本继续生效;反之先跳过 trick 直接上 LiDAR,V2-99 阶段还要重做
关键 insight:Phase 2(Camera+LiDAR 融合)是论文创新点,但创新点的"提升幅度"必须在已经把所有已知 camera-only trick 用尽的 baseline 上量化,否则审稿人会说"提升来源不明"。Phase 1 的 ROI 不是"涨几个点",是"让 Phase 2 的涨点可信"。

A1 — Refine2D 辅助 2D 监督头 P0

来源:chenxi/onemodel(已实战验证) 成本:🟢 低 预期:+0.02 ~ +0.03 AMOTA / +0.01 mAP 训练:warm-start fine-tune ~2000 iter

怎么改:每个 3D anchor 中心投影到 6 个相机平面 → 双线性采样 image FPN feature → 一个轻量 MLP(共享所有相机)预测 (dx, dy, log_w, log_h) 和 num_cls 个 logits → 用 2D bbox 监督。2D GT 自动从 3D GT 的 8 corners 投影生成,无需额外标注。推理时整个模块跳过(if not training: return),零开销。

为什么有效? Sparse4D 的 deformable aggregation 是从 anchor 周围采 keypoint 聚合 image feature,但 keypoint 位置依赖 anchor 已经"差不多准",这是个鸡生蛋问题(anchor 位置不准 → keypoint 采错地方 → feature 错 → anchor 学不准)。Refine2D 给每个 anchor 一个独立的 2D 监督信号(强迫"这个 anchor 中心点在图像上的位置和大小要预测对"),反向 propagate 到 image backbone 后,backbone 学到的 feature 就更"location-aware",前面的 deformable 采样质量自然提升。

关键食谱(必须严格遵守,否则会崩):

  • 必须 fine-tune,不能 from-scratch:从 baseline ckpt warm-start,跑 ~2000 iter 即可
  • 必须 paramwise lr 控制:全局 lr 降 10x(4e-5),aux head 单独 lr_mult=10x(实际 4e-4),backbone lr_mult=0.1x(实际 4e-6 几乎冻住)
  • 用 gt_source='project' 模式(geometric 投影)。不要用 real_simota(chenxi 的工程已踩坑:AMOTA 从 0.677 跌到 0.419,长尾类崩盘)
  • per-class loss weight 借用 chenxi 经验值(other_vehicle 3.0×, van 2.0×,其他 1.0×)作起点,我们 R50 设定下不一定 transfer,可在 A1 ckpt 上做 7-point sweep 重新调

同源工程实测:chenxi 的 RepVGG+LiDAR 设定下,refine2d_highlr recipe 把 AMOTA 从 ~0.68 提到 0.7119(refine2d_highlr_top3000_thr025.log)。

A2 — MemoryBank 替代 InstanceBank P1

来源:chenxi/onemodel(已实战验证) 成本:🟢 低 预期:IDS↓,AMOTA 略升 训练:从 A1 ckpt 接着训 ~50 epoch

怎么改:把原 InstanceBank 的 ring buffer(num_temp_instances=8,只能存最近 8 帧 = 4 秒)换成独立容量的 MemoryBank(num_memory_instances=512,容量 64×)。temporal feature 不再随 ring buffer 滚动覆盖,而是用置信度 decay 维护一个长程 cache。

为什么有效? nuScenes 2 Hz 采样下,8 帧 ring buffer 只能记住 4 秒前的物体。一个被遮挡 ≥4 秒的车再出现,原 InstanceBank 已经把它的 query feature 完全冲掉了,只能给它分新 ID(IDS+1)。512 容量的 MemoryBank 能记住几十秒前出现过的 instance,长遮挡 case 直接用 cached feature 续上同一个 ID。IDS 主要降在"长遮挡 reappear"这种 case 上,纯 detection mAP 影响很小。

风险:容量太大也会引入 false continuation(把过期 track 错误延续)。chenxi 默认 512 是经验值,可能需要在 256/512/1024 三档做小 ablation 找最优。

A3 — ContrasTR loss P0

来源:ContrasTR (WACV 2024) 成本:🟢 低(纯 loss 加法) 预期:+0.01 ~ +0.03 AMOTA / IDS↓ 训练:从 A2 ckpt 接着训 ~30-50 epoch

怎么改:在 track head 输出的 query feature 上加一个 InfoNCE-style contrastive loss。同 GT instance ID 的 query 互相拉近(positive pair),不同 ID 的 query 互相推远(negative pair)。

为什么有效? Sparse4D-v3 默认的关联策略是 IoU + classification score,但 query feature 本身从未被显式优化为 "ID-discriminative"。两个外形相近、位置相近的同类物体(比如两辆并排开的白色 SUV),Sparse4D 的 query feature 在 embedding 空间可能几乎重合,跨帧关联时极易换 ID。

ContrasTR 让网络在训练时显式学习 "同 ID 的 query 应该有相似 embedding,不同 ID 的应该正交",query feature 自身就成了一个强 ID-discriminator。关联模块在推理时不变,但喂给它的 feature 质量大幅提升,IDS 直接降。

A4 — PF-Track Spatial-Temporal Reasoner P0

来源:PF-Track (CVPR 2023),本地有 ../PF-Track/ 代码可复用 成本:🟡 中(需要把 PF-Track 模块嫁接进来) 预期:+0.03 ~ +0.05 AMOTA / IDS 降 ~50% 训练:从 A3 ckpt 接着训 ~50 epoch

怎么改:在 InstanceBank.cache → 下一帧 decoder 之间插入 SpatialTemporalReasoner(一组 Transformer block)。它做两件事:

  1. Past reasoning:对历史 3 帧的 query feature 做 cross-attention,refine 当前帧 query
  2. Future prediction:基于 motion model 预测 query 在未来 8 帧的位置,用于 inactive(被遮挡)track 保活
为什么有效? Sparse4D 的"时序"其实只是 "把过去帧的 query feature 拼到当前帧 decoder 输入" 这种隐式 temporal aggregation,网络没有任何显式的 motion model。一个连续高速运动的物体,网络只能"事后"猜它的位置,跟踪滞后明显。

PF-Track 的 ST Reasoner 显式建模"物体在 ego coord 下的运动",主动 predict 物体未来位置。被短暂遮挡的 track 不再被丢弃,而是用 motion prediction 维持位置直到再次观测到。这是 IDS 大幅下降的主要来源。

同源工程实测:PF-Track 论文里 nuScenes val AMOTA 从 0.43 → 0.479(单独 +0.05),IDS 从 1100+ 降到 ~570(降 ~48%)。

A5 — Birth/Death 状态机 P1

来源:Poly-MOT (IROS 2023) / 经典 MOT 思路 成本:🟢 极低(只改 InstanceBank 的 ID 分配逻辑) 预期:IDS↓,纯 IDS 优化 训练:不需要重训,只在推理时改逻辑(post-process)

怎么改:替换原 prev_id++ 暴力 ID 分配,改成三态机:

  • Tentative(试用期):新出现的 query 先进试用期,需要连续 N 帧(默认 3)高置信才转 Confirmed
  • Confirmed(确认):正常 track,丢失后允许 K 帧(默认 5)的"宽限期"才转 Dead
  • Dead(死亡):彻底丢弃,后续不再关联
为什么有效? nuScenes 评测 IDS 的两大主因:
(1) "昙花一现 false positive" — 单帧偶尔的高置信 FP 直接拿到一个 ID,下一帧消失,IDS+1
(2) "短暂丢失再出现" — 真物体被遮挡 1-2 帧丢失,Sparse4D 默认立刻把这个 ID 释放,物体再出现时分新 ID,IDS+1

状态机:Tentative 期挡掉 (1) 的所有 FP(因为它们撑不到 N 帧高置信),宽限期 K 解决 (2) 的短遮挡(直接复用原 ID)。这个 trick 无需训练,纯推理逻辑,但 IDS 通常能降 30-50%。

A6 — HQD + 物理约束 DN noise P1

来源:S2-Track (ICML 2025) D1 + D4 模块 成本:🟢 低(改 DN noise 生成 + decoder 多层级注入) 预期:+0.01 ~ +0.02 AMOTA(主要加速收敛 + 抑制过拟合) 训练:从 A5 ckpt 接着训 ~30 epoch

怎么改:

  • HQD (Hierarchical Query Denoising):DN query 在 多个 decoder 层级都注入(原 Sparse4D 只在第一层注入),让深层 decoder 也有"已知答案"的监督信号
  • 物理约束 DN noise:原 DN noise 是纯几何高斯扰动(包括朝向 ±180° 的随机翻转),物理上不合理。改成 noise 满足物理可行约束:速度噪声不超过物体最大加速度,朝向噪声不超过物体最大转向角速度
为什么有效? DN(denoising query)是 DETR 系加速收敛的关键技巧:训练时往 GT box 上加高斯噪声当作 "已知 GT" query,network 学习去噪。原 Sparse4D 的 DN noise 是纯几何噪声,会出现"一辆车朝向忽然反转 180°"这种物理不可能 case,网络浪费容量在学习不可能出现的分布上。

HQD 增加监督密度(每一层 decoder 都有 DN supervision),收敛更快;物理约束 noise 让 DN 的"先验分布"和真实分布对齐,网络容量利用率更高。这两个 trick 主要影响收敛速度而不是 final 数字,但在固定 epoch 数下,收敛快 = final 数字略高。

A7 — UPD(Uncertainty-aware Probabilistic Decoder) P1

来源:S2-Track B3 模块 成本:🟡 中(改 attention 内部,query 输出 covariance) 预期:+0.01 ~ +0.02 AMOTA(长尾类受益最大) 训练:从 A6 ckpt 接着训 ~50 epoch

怎么改:让 decoder query 不只输出 (x, y, z, w, l, h, sin_yaw, cos_yaw, vx, vy) 这 10 维点估计,还输出一个 covariance matrix(对角假设下就是 10 个 sigma)。关联时用 Mahalanobis distance(考虑 sigma)代替 Euclidean / IoU。

为什么有效? 远处物体(80 米外)的检测 inherently 不确定 — 哪怕真值就在那,网络也只能给一个粗略位置。Sparse4D 默认用统一 IoU threshold 关联远近物体:近处物体几乎没漂移,IoU 阈值卡得严没问题;但远处物体跨帧位置波动 ~1 米,IoU 直接掉到 0.2,换 ID。

UPD 让 query 自己输出 sigma:近处物体 sigma 小(关联严格),远处 sigma 大(关联宽松),自适应阈值。长尾类(行人 / 自行车 / 远处车辆)IDS 改善最明显,主类影响有限。

4. Phase 1 leave-one-out ablation

A7 全开后(7 个 trick 都打开,得到 baseline+ all 数字),依次关闭一个 trick跑 7 次完整训练。这 7 个数字 + A0 + A7 全开,组成论文 ablation table 的核心 7 行。

实验关闭的 trick用途
A7 全开—Phase 1 终点(camera-only 高质量 baseline)
A7 - Refine2DA1验证 Refine2D 的边际贡献
A7 - MemoryBankA2验证长程记忆的边际贡献
A7 - ContrasTRA3验证 contrastive loss 的边际贡献
A7 - PF-Track STA4验证显式 motion model 的边际贡献
A7 - Birth/DeathA5验证状态机的边际贡献
A7 - HQD/物理 DNA6验证训练稳定性 trick 的边际贡献
A7 - UPDA7验证不确定度 decoder 的边际贡献

leave-one-out 比"加法式"更严谨,因为加法式只能告诉你"加 trick X 之前 / 之后",但 trick 之间可能有非线性交互(比如 PF-Track + UPD 协同作用 > PF-Track 单独 + UPD 单独)。leave-one-out 直接告诉你"全开状态下,trick X 不可或缺的程度"。

F0 — LiDAR-only baseline(CenterPoint)P1

来源:CenterPoint(mmdet3d 现成代码) 成本:🟡 中 预期:AMOTA 0.69(论文数字,纯参照) 训练:1 次 ~12-18h

怎么改:不在 Sparse4D 框架内做,直接用 mmdet3d 的 CenterPoint config 跑一次 8 卡训练,得到 LiDAR-only 的 nuScenes val AMOTA。

为什么必须做这一行? 论文必须回答审稿人的"你的融合是不是只是把 LiDAR 信息塞进来,没有真正的 fusion design?"。F0 给出 "纯 LiDAR 能到 0.69" 这个上界,我们的 F5 多模态如果能到 0.70+,说明融合带来了 LiDAR 自身做不到的 marginal gain。这是论文 contribution 成立的必要数字。

F1 — LiDAR backbone + 双模态 sampling P0

来源:嫁接 chenxi/onemodel 的 hybrid_encoder + pts_* backbone 成本:🟡 中(代码已有,主要是 port) 预期:+0.05 ~ +0.08 AMOTA / +0.04 ~ +0.06 mAP 训练:1 次 ~18-24h

怎么改:

  1. 加 LiDAR backbone:VoxelEncoder(SECOND 风格,sparse 3D conv)→ BEVNeck → 输出 256 通道 BEV feature(grid 192×192)
  2. 修改 InstanceBank query 的 sampling 路径:每个 query 不只从 image FPN 采样 keypoint,同时从 LiDAR BEV 采样一个 keypoint(query 的 3D anchor center 投影到 BEV grid → bilinear 采样)
  3. 两路 feature 用 sum 或 concat 后送进 deformable aggregation(F1 默认 sum,F2 会换成 attention 加权)
为什么有效? image 的优势:dense texture / color / fine-grained class info(分得清"这是 trafficcone 还是 pedestrian");
image 的劣势:depth 模糊(单目深度估计误差远 > 1 米,远距离更差),遮挡敏感;
LiDAR 的优势:精确 depth / 3D shape(直接测距,误差 ~5 cm);
LiDAR 的劣势:texture 缺失(纯几何点云分不清两辆同形状车),稀疏类难分(行人和路灯杆点云相似)。

两个模态的优劣势几乎完全互补。F1 把两路 feature 简单求和,query 同时拿到"我应该是什么(image)+ 我精确在哪(lidar)",远距离物体定位 / 复杂语义类区分都受益。

同源工程实测:chenxi 的 RepVGG-LiDAR (相当于 F1 + 一些其他 trick) 在 nuScenes val 上 AMOTA 0.68+,远超 camera-only 0.55-0.58。

F2 — FUTR3D MAFS(Modality-Adaptive Feature Sampling)P1

来源:FUTR3D (CVPRW 2023) 成本:🟡 中(改 sampling head) 预期:+0.01 ~ +0.02 AMOTA 训练:1 次 ~18-24h

怎么改:把 F1 的"image_feat + lidar_feat 求和"换成 attention 加权:

fused = w_img * image_feat + w_lid * lidar_feat
where (w_img, w_lid) = softmax(MLP([query_feat, image_feat, lidar_feat]))

加权系数对每个 query 单独学习,让 query 自己决定"我这次更相信哪个模态"。

为什么有效? F1 的固定权重对所有 case 一视同仁,但 modality dominance 是 case-by-case 的:
(1) 远距离小物体:LiDAR 反射稀疏(可能只有 3-5 个点),image 的语义特征更可靠
(2) 近处大物体被遮挡:image 看到的是遮挡物,LiDAR 还能扫到一部分,LiDAR 更可靠
(3) 下雨夜晚:image 噪声大,LiDAR 反而更稳定

MAFS 让 query 根据自身情况自适应权重,理论上严格 ≥ F1 的固定权重。但实测 +0.01 ~ +0.02 提升不算特别大,主要价值是为 F4 的 masked-modal training 铺垫(只有自适应权重,modality drop 才有意义)。

F3 — CMT 位置编码对齐 P1

来源:CMT (ICCV 2023) 成本:🟡 中(改 PE 模块) 预期:+0.01 ~ +0.02 AMOTA 训练:1 次 ~18-24h

怎么改:

  • image token PE:从原 2D pixel sin/cos PE 换成 frustum 3D PE(根据相机内外参,把 2D pixel 反投影到 3D 视锥的多个 depth 层,每层一个 3D 坐标 → sin/cos PE)
  • LiDAR token PE:从原 BEV grid index PE 换成 BEV 3D 坐标 PE(直接用每个 BEV grid cell 的物理坐标 (x, y, 0) 做 sin/cos PE)
  • 两路 PE 在同一个 3D 物理空间对齐
为什么有效? Sparse4D 默认 image PE 是 2D 像素空间,LiDAR PE 是 BEV grid 空间,两路 PE 不在同一个空间。Transformer attention 算 Q·K 时,PE 数值大的一边会主导(常常是 LiDAR 因为 BEV grid index 数值范围更大)。这种 "PE 偏向" 让 attention 不再基于真实 3D 距离,而是 PE 数值大小。

CMT 把两路 PE 都映射到 3D 物理空间,attention 基于真实 3D 距离。一个 query 在物理空间近的 image patch 和 LiDAR voxel 都会被等量关注。

F4 — Masked-modal training P0

来源:CMT 成本:🟢 低(几行 mask 代码) 预期:mAP 持平,modality dropout 鲁棒性大幅提升 训练:1 次 ~18-24h

怎么改:训练时,每个 batch 以 30% 概率整体 zero-out image FPN feature(模拟相机失效),以 30% 概率整体 zero-out LiDAR BEV feature(模拟 LiDAR 失效);60% 概率两路都正常。推理不变。

为什么有效? 没有 masked training 时,网络会在训练中形成 "modality shortcut" — 比如 LiDAR 总是给出准确 depth,网络就不再训练 image 的 depth 预测能力(反正 LiDAR 帮我做了)。一旦推理时 LiDAR 失效,网络立刻崩盘(mAP 可能直接腰斩)。

Masked training 强制网络两种情况都要应付:纯 image 也能做、纯 LiDAR 也能做、双模态时还能融合。代价是训练时网络更难收敛(loss 噪声大),但推理时:
(1) graceful degradation:车上传感器失效后性能不崩盘
(2) 4 种推理模式都可用:cam+lidar / cam-only / lidar-only / random-drop,这是论文 "对标 DualViewDistill" 的核心 story

F4 是 paper story 的关键拼图:DualViewDistill 0.669 是 camera-only 推理(用 LiDAR 做 distillation 但不参与推理),我们的 F4+ 模型可以做所有推理 setting:cam-only(对比 DualViewDistill)、cam+lidar(SOTA 数字)、lidar-only(对标 CenterPoint),一篇 paper 同时占 3 个 leaderboard 位置。

F5 — BEVDepth 显式深度监督 P1

来源:BEVDepth (AAAI 2023) 成本:🟡 中(替换 DenseDepthNet) 预期:+0.01 ~ +0.02 AMOTA 训练:1 次 ~18-24h

怎么改:Sparse4D 自带的 DenseDepthNet 用稀疏的 anchor 中心 depth作为监督(每个 image 只有几百个监督点),改成用 LiDAR 投影点作为 dense depth GT(每个 image 有 1-2 万个监督点,密度高 100x)。Loss 变成 dense regression。

为什么有效? image FPN 的 depth 预测精度直接决定 image-LiDAR 融合质量 — depth 不准的话,image 的 query 在 LiDAR BEV 上采样位置就错了,F1-F3 的 fusion design 全部白搭。

DenseDepthNet 的稀疏监督是 "在已知物体中心点 depth 准就行",但 image FPN 是个全图 representation,只有几百个监督点会让大部分像素的 depth 预测处于"无监督"状态。

BEVDepth 用 LiDAR 投影点做 dense GT,每个像素都有 depth GT,FPN 的 depth 表征质量大幅提升,后续 image→3D frustum 投影更准,fusion 质量自然更高。这是个"通过监督密度提升 backbone 质量"的 trick。
